SMART DISK CLEANUP APP - REQUIREMENTS
==========================================
Doc purpose: running record of requirements gathered during planning discussion.
Status: V1 BUILT AND VERIFIED. Core architecture, safety model, and all 11
planned features have been implemented, unit-tested, and run end-to-end.
A handful of known gaps remain between "designed" and "fully wired into the
UI" - see section 5.

Repository: https://github.com/saaid10/disk-cleaner (private)

1. PURPOSE
----------
Personal Windows utility to clean up hard drive / SSD clutter intelligently:
find junk, duplicates, large/old files, and keep the Desktop organized -
without ever risking files the user actually cares about.

2. PLATFORM / ARCHITECTURE
---------------------------
- Frontend: native Windows desktop app, C#/.NET 9 (WPF), MVVM via
  CommunityToolkit.Mvvm.
- Solution layout (BUILT):
    * DiskCleaner.Core - all business logic (scanners, quarantine, org-
      anizer rules, formatting, data access). No WPF/UI dependency, fully
      unit-testable.
    * DiskCleaner.App - WPF shell, ViewModels, Views, tray icon, Windows-
      specific interop (shortcut resolution, folder picker).
    * DiskCleaner.Core.Tests - xUnit test project. 121 tests, all passing.
- Local storage: SQLite via Microsoft.Data.Sqlite (raw ADO.NET, not EF
  Core - kept lightweight for a single-table-per-concept personal DB), one
  local DB file at %LocalAppData%\DiskCleaner\diskcleaner.db.
  - Stores: settings (key/value), whitelist categories, thresholds,
    protected-folder list, Safe Haven path, quarantine metadata (original
    path, deleted date, 7-day expiry), custom organizer rules, cleanup/
    scan history for reporting.
- Background operation: app runs with a system tray icon (NotifyIcon via
  UseWindowsForms) so scheduled whitelisted auto-clean can run without the
  main window open. Closing the window hides to tray instead of exiting;
  tray "Exit" is the real quit path.
- Elevation model (IMPLEMENTED): runs unelevated by default. When
  quarantining Windows Update leftovers fails with access-denied, offers
  a "Retry as Administrator?" prompt; accepting relaunches the app exe in
  a headless mode (--elevated-move-folder) via a UAC prompt to perform
  ONLY the raw file moves, then exits - the main process stays unelevated
  and owns all database bookkeeping (ElevatedMoveHelper,
  QuarantineService.RecordExternallyMovedItem). Note: a real UAC prompt
  runs on Windows' secure desktop, isolated from automation by design -
  the plumbing is built and unit-tested but the actual click-through-a-
  UAC-prompt path needs a manual end-to-end check by the user.

3. CORE FEATURES
-----------------

3a. Smart engine (decision - IMPLEMENTED)
    - DECISION MADE: rule-based heuristics only. No ML, no LLM.
      Reasoning: personal-use, single-user tool - a learned/trained model
      is overkill engineering weight for the payoff, and rules are
      deterministic/explainable ("this is in Temp/ and >30 days old") from
      day one with no cold-start period.
    - Considered and rejected: rules + local ML scoring (needs weeks of
      accept/reject history before it's useful - too much burden for a
      personal tool); rules + LLM-assisted classification (adds cost/
      latency/nondeterminism for a tool whose whole point is predictability
      around deletion).
    - Built: WhitelistPolicy hard-codes which categories can ever be
      auto-clean-eligible (see 3b) - a safety guarantee enforced in code,
      not just documented intent.

3b. Delete safety & quarantine (decision - IMPLEMENTED)
    - DECISION MADE: hybrid model, per category:
        * Whitelisted categories (user explicitly opts a category in) can
          be auto-cleaned on a schedule without asking each time.
        * Everything else always requires manual review/confirm before
          being touched.
    - DECISION MADE: nothing whitelisted is ever hard-deleted immediately.
      Auto-cleaned files move to a recoverable quarantine/undo folder and
      are only permanently deleted after 7 days. Restorable at any point
      during that window.
    - Windows Update leftovers (Windows.old, SoftwareDistribution\Download)
      are NEVER whitelist-eligible even though they're "junk" - deleting
      them is semi-irreversible (blocks OS rollback) and needs elevation,
      so they always require manual confirm regardless of settings.
    - Built: QuarantineService (move/restore/purge-after-7-days), backed
      by QuarantineRepository. Restore refuses to overwrite a file that
      reappeared at the original path (throws
      QuarantineRestoreConflictException) instead of clobbering it.
      Quarantine screen in the app shows active items, per-item countdown,
      restore, and a manual "Purge Expired" action.
    - Fixed (reported by user): aggregate-location categories (browser
      cache, Windows temp, Windows Update leftovers - see 3g) used to
      quarantine the WHOLE folder as one atomic move. Since Windows Temp
      and browser cache folders almost always have at least one file
      locked by a running process, that single move failed entirely -
      user reported "3.18 GB shown, 1 failed (in use or access denied),
      nothing deleted." Fixed via QuarantineService.QuarantineFolderContents:
      quarantines the folder's immediate contents item-by-item instead of
      the folder as a whole, so locked files are skipped individually and
      everything else still gets quarantined. Verified with a unit test
      that holds a real file lock open during the call.
    - Fixed: bulk quarantine actions (Cleanup Suggestions "Delete
      Selected") now run off the UI thread (Task.Run) - proactively
      fixing the same freeze-on-synchronous-I/O bug class caught earlier
      in Cleanup Suggestions/Treemap loading, since quarantining hundreds
      of individual files via QuarantineFolderContents on the UI thread
      would have frozen the window the same way.
    - Added: confirmation dialog before bulk delete ("Quarantine N
      item(s), reclaiming up to X? Reversible for 7 days.") - scoped to
      the bulk "Delete Selected" action only, not per-item Duplicates/
      Large&Old Files clicks, since a modal per single-file click would
      just be friction for low-blast-radius actions.
    - QuarantineService fires a Changed event (once per logical action,
      not once per file during bulk folder quarantine) that Dashboard and
      Quarantine screens subscribe to for auto-refresh, instead of
      requiring a manual Refresh click after cleanup elsewhere.

3c. Protected folders & Safe Haven (decision - IMPLEMENTED)
    - DECISION MADE: both mechanisms, folder-based exclusion as primary.
        * Folder-based exclusion: user marks any existing folder as
          protected via settings. Recursive by default - protecting a
          folder protects everything under it automatically.
        * Safe Haven folder: one dedicated folder where anything placed
          inside is automatically off-limits, no marking needed - a quick
          catch-all for loose files that don't belong to an already-
          protected folder.
    - Protected/Safe Haven content is excluded from scanning entirely (not
      just from deletion), so it never appears in suggestions either.
    - Built: PathProtectionService.IsProtected(path), consumed by every
      scanner (junk, duplicates, large/old files, treemap). Protected
      Folders screen in the app: add/remove folders, set Safe Haven path,
      both via a native folder-browse dialog.

3d. Desktop Organizer (decision - IMPLEMENTED)
    - DECISION MADE: on-demand trigger only (button), not a continuous
      background watcher. Reasoning: auto-sorting the instant a file lands
      is annoying in practice - files often need to sit loose temporarily
      (mid-download, about to be attached to an email).
    - DECISION MADE: two-layer sorting logic.
        * Base layer: type-based mapping by extension (.pdf/.docx/.xlsx ->
          Documents, .png/.jpg/.gif -> Images, .zip/.rar -> Archives,
          .mp4/.mkv -> Videos, .mp3/.wav -> Audio, everything unmatched ->
          generic "Other" bucket).
        * Override layer (built-in preset, shipped): game-platform
          detection for .exe/.lnk before falling back to the generic
          "Programs" bucket.
            - Shortcuts (.lnk): resolves the shortcut's target path via
              the WScript.Shell COM object; if it points into a Steam/
              Epic Games/GOG Games/Battle.net/Origin Games install
              directory, moves to a "Games" folder instead of the generic
              bucket. Unresolvable/non-game shortcuts fall back to
              "Other" rather than being left untouched.
            - Installer filenames: keyword match on common installer
              names (SteamSetup, EpicGamesLauncherInstaller, GOG_Galaxy,
              GOGGalaxySetup, BattlenetSetup, OriginSetup,
              OriginThinSetup).
        * Date-based sorting and a user-facing custom-rule-builder UI are
          NOT built (still out of scope for v1 - see section 4). The data
          model (OrganizerRule/OrganizerRuleRepository) exists for a
          future custom-rule UI but nothing in the app writes to it yet.
    - DECISION MADE: existing subfolders already on the Desktop are left
      alone by default - only loose files sitting directly on the Desktop
      are sorted.
    - DECISION MADE: reversible via a simple "Undo last organize" (reverts
      the most recent batch move). Execute() also refuses to overwrite an
      occupied destination (skips instead of clobbering).
    - Note: on-demand smart "nudge" notification when loose file count
      crosses a threshold (mentioned in earlier discussion) was NOT built.

3e. Duplicate file finder (decision - IMPLEMENTED)
    - Content-hash based (SHA-256, not filename/size alone), to guarantee
      accuracy. Two-stage for performance: group files by size first
      (cheap), then hash only files that share a size with at least one
      other file (avoids hashing every file on the drive).
    - On-demand scan only (not background/scheduled) - hashing is CPU/IO
      heavy. Scoped to the user's configured Scan Roots (Settings), not
      the whole drive by default.
    - Always manual-review tier (not whitelist-eligible) - which copy to
      keep is a judgment call, not a universally safe default. Duplicates
      the user chooses to remove go through the same quarantine flow as
      other manual deletions.
    - Protected folders / Safe Haven contents are excluded from duplicate
      scans (per 3c). Empty files are ignored (not meaningful duplicates).

3f. Large & old file finder + visual disk map (decision - IMPLEMENTED)
    - Sortable list view: file size, last-accessed date, path. Default
      filter suggestion: files >100MB not accessed in 90+ days (both
      thresholds user-configurable in Settings, not hardcoded). Noted in
      code: NTFS last-access-time tracking is often disabled by default
      on Windows for performance, so this signal can lag reality on some
      systems - still the closest available without a separate usage
      tracker.
    - Visual disk map: treemap-style view of drive/folder structure,
      click a folder rectangle to drill in, "Up" to go back. Loads
      asynchronously with progressive streaming updates - items appear as
      soon as their size is known rather than an all-or-nothing wait (a
      drive root can show most items within a second even while the
      largest folder is still being sized).
    - Fixed (user-reported): a real C:\ root both loaded very slowly and
      rendered as mostly-unreadable slivers past the first few items.
      Two separate root causes, both fixed:
        * Layout: replaced the original simple single-axis slice layout
          with the standard squarified treemap algorithm (Bruls/Huizing/
          van Wijk) - groups items into rows/columns keeping each
          rectangle's aspect ratio near 1:1 instead of slicing everything
          along one axis, so dozens of children stay legible. Regression-
          tested with 25 equal-sized items asserting no rectangle exceeds
          a 6:1 aspect ratio.
        * Performance: sizing every subfolder's full recursive tree now
          runs as one flat parallel operation across every leaf directory
          of every subfolder combined, rather than nesting parallel
          operations (subfolder-level parallelism alone doesn't help when
          one huge folder like C:\Windows dominates on its own; nesting a
          second parallel layer inside that didn't help either - two
          nested parallel operations compete for the same finite core
          count without actually finishing faster). A user-configurable
          minimum-size filter (Settings, default 5MB) also buckets tiny
          items into a single "Other (small items)" node.
    - Treemap color-coding reuses the same file-type categories as the
      Desktop Organizer's type buckets (Documents/Images/Archives/
      Installers/Videos/Audio/Other), plus a "Folder" category for
      subfolder nodes, for a consistent visual language across the app.
    - Always manual-review tier - never auto-deleted, only surfaced as
      suggestions.
    - Fixed: the Disk Scan/Treemap screen header now shows the current
      drive's per-drive used/free breakdown from 3m (previously
      Dashboard-only).

3g. Category-aware junk scanning (decision - IMPLEMENTED)
    - In-scope categories, BUILT:
        * Browser cache (Chrome/Edge known cache paths; Firefox profile
          cache2 folders auto-discovered)
        * Windows temp folders (%TEMP%, C:\Windows\Temp)
        * Dev build/dependency folders (node_modules, obj, bin, dist,
          .next, target) - recursive scan, does not descend into a
          matched folder once found
        * Log files (*.log older than a configurable age, within the
          user's configured Scan Roots)
        * Windows Update leftovers (Windows.old, SoftwareDistribution\
          Download) - see 3b, always manual; elevation retry available
          via UAC prompt if access is denied (see section 2)
        * Downloads folder (3o)
    - Built: Recycle Bin size reporting + "Empty Recycle Bin" direct
      action (RecycleBinService, SHQueryRecycleBin/SHEmptyRecycleBin
      P/Invoke). Not routed through QuarantineService - the Recycle Bin
      already IS a quarantine, so this is a direct action with its own
      confirmation dialog that explicitly notes it is NOT recoverable via
      the app (unlike everything else on the Cleanup Suggestions screen).
      Surfaced as a summary card on the Cleanup Suggestions screen.
    - Deferred / out of scope for v1 (unchanged): orphaned game-install
      leftovers (workshop temp files, old patch caches, etc.) - reliable
      detection needs per-launcher knowledge/APIs not worth building for
      a personal tool right now.
    - Whitelist-eligible (enforced by WhitelistPolicy in code): browser
      cache, Windows temp, dev build/dependency folders, log files.
    - Always manual-review tier (enforced by WhitelistPolicy in code):
      Windows Update leftovers, duplicates, large/old files, Downloads
      (3o) - never auto-clean-eligible even if somehow present in a
      whitelist setting.

3h. Scan scope (decision - IMPLEMENTED)
    - All local fixed drives (C:, D:, etc.) supported for the Dashboard's
      drive overview - always shown, no opt-in needed.
    - Dev-build/log/duplicate/large-old-file scans are scoped to user-
      selected "Scan Roots" (Settings screen: add/remove folders via a
      native folder-browse dialog) rather than the whole drive by default.
    - External/removable drives: excluded from the Dashboard by default;
      Settings now lists currently-attached removable drives
      (DriveSpaceService.GetAvailableRemovableDrives) as opt-in checkboxes
      so the user can explicitly include a specific USB/external drive
      without needing to know its drive letter in advance.
    - Network drives: out of scope for v1 (unchanged).

3i. Scheduling (decision - IMPLEMENTED)
    - Whitelisted categories (3b/3g) run on a user-configured interval
      (Settings: "Auto-clean interval (days)", default 7) via an hourly
      due-check timer (AutoCleanBackgroundService) running in the tray
      process. All other scan types (duplicates, large/old files, manual
      Cleanup Suggestions) are on-demand only, triggered by clicking
      "Scan" - not scheduled, since they're review-required anyway.
    - Background scan failures are logged to a local file
      (%LocalAppData%\DiskCleaner\app.log) instead of silently swallowed
      or crashing the app.

3j. Before/after reporting (decision - IMPLEMENTED)
    - CleanupReportBuilder aggregates total bytes reclaimed + per-category
      breakdown, either from a just-completed action's quarantined items
      or from historical CleanupHistory rows.
    - Built: CleanupReportWindow shows this after Cleanup Suggestions'
      "Delete Selected" completes (and after an elevated-retry pass for
      Windows Update leftovers) - total reclaimed, per-category
      breakdown, and the full list of quarantined items. Duplicates and
      Large&Old Files still show a one-line status per item (no modal for
      single-item clicks - would be excessive friction there); the
      Quarantine screen separately covers "what's pending deletion" with
      live countdowns.

3k. Main screens / navigation (decision - IMPLEMENTED, structure changed
    from original draft)
    - BUILT: 9 screens behind a sidebar shell (ShellViewModel), lazily
      created and cached per screen so switching tabs doesn't re-scan:
        * Dashboard - per-drive used/free overview (3m), manual refresh
        * Disk Scan - treemap drill-down (3f)
        * Cleanup Suggestions - junk-scan review queue (3g, 3o) including
          Downloads, checkbox multi-select + a single "Delete Selected"
          bulk action (plus Select All/Select None) rather than a
          per-row instant button
        * Duplicates - grouped duplicate files (3e), per-file quarantine
        * Large & Old Files - sortable list (3f), per-file quarantine
        * Quarantine - active items, countdown, restore, purge expired
        * Desktop Organizer - organize-now + undo-last (3d)
        * Protected Folders - manage exclusions + Safe Haven (3c)
        * Settings - whitelist opt-ins, scan roots, all thresholds
    - Change from the original draft: Duplicates and Large & Old Files
      were originally sketched as part of a single combined "Cleanup
      Suggestions" review queue. They were built as separate screens
      instead, since their scan triggers, thresholds, and result shapes
      are different enough that combining them would have made one screen
      overloaded. Cleanup Suggestions now covers the category-based junk
      scan (3g) plus Downloads (3o).
    - Change (later): Cleanup Suggestions was originally per-row instant
      delete (a "Quarantine" button per line). Changed to checkbox
      multi-select + one bulk "Delete Selected" action when Downloads was
      added, since reviewing potentially hundreds of Downloads files one
      button-click at a time doesn't scale - the user now checks
      everything they want gone, then confirms once.

3l. File/app size display format (decision - IMPLEMENTED)
    - DECISION MADE: every size shown anywhere in the app uses one shared
      adaptive-unit formatter (FileSizeFormatter, Core) - not raw bytes.
    - Unit priority: GB first, then MB, then KB, then bytes - i.e. use the
      largest unit that keeps the displayed number >= 1:
        * >= 1 GB   -> show as GB (e.g. "2.34 GB")
        * >= 1 MB   -> show as MB (e.g. "487.10 MB")
        * >= 1 KB   -> show as KB (e.g. "312 KB")
        * < 1 KB    -> show as bytes (e.g. "480 B")
    - 2 decimal places for GB/MB, whole numbers for KB/bytes. Formatted
      with invariant culture (not the OS locale) so the decimal separator
      is always "." regardless of the machine's regional settings - found
      during testing that the dev machine's locale used "," and broke the
      original locale-aware formatting.
    - Applies to single files, folders (aggregate size), and summary
      totals alike - used in Dashboard, Cleanup Suggestions, Duplicates,
      Large/Old Files, Treemap, Quarantine, Desktop Organizer status text.

3m. Drive space overview (decision - IMPLEMENTED)
    - DECISION MADE: Dashboard shows, per fixed drive (plus any opted-in
      removable drive, 3h), a used/free breakdown: total capacity, space
      used, space free (via the shared size formatter, 3l) plus a visual
      two-color proportion bar.
    - One card per drive. Auto-refreshes on QuarantineService.Changed (any
      cleanup action anywhere in the app) in addition to the manual
      "Refresh" button.
    - Disk Scan/Treemap header now shows the same breakdown for whichever
      drive the current folder is on (3f).

3n. SSD vs HDD handling (decision - unchanged, correctly out of scope)
    - DECISION MADE: no filesystem/drive-type-specific cleanup logic
      needed - junk/duplicate/large-file cleanup works the same way
      regardless of SSD or HDD. SSD-specific health features (TRIM
      triggering, SMART/wear-level monitoring) are a different problem
      domain (disk health, not disk cleaning) and are OUT OF SCOPE unless
      requested later. Nothing built here, nothing needed.

3o. Downloads folder scanning (decision - IMPLEMENTED)
    - DECISION MADE: Downloads accumulates a lot of clutter (installers,
      one-off attachments, archives) and deserves its own scan category
      rather than requiring the user to add it manually as a Scan Root.
    - Lists files sitting directly in the Downloads folder (not recursive
      - a subfolder the user already created there is treated as
      intentional organization, same rule as the Desktop Organizer
      leaving existing subfolders alone). Each file is its own row (not
      aggregated like browser cache/temp), showing size and last-modified
      date so the user can judge age at a glance.
    - Resolved via the default location (%USERPROFILE%\Downloads) - no
      Windows Known-Folder COM lookup for a user-relocated Downloads
      folder; not worth the interop complexity for a personal tool.
    - DECISION MADE: always manual-review tier, NEVER whitelist-eligible
      (enforced in WhitelistPolicy) - unlike browser cache or temp files,
      Downloads content is unpredictable (could be an installer not yet
      run, a document, an unextracted archive) so it can never be treated
      as safe-to-auto-delete.
    - Surfaced in the Cleanup Suggestions screen (3k) alongside the other
      junk categories, using the same checkbox multi-select + bulk delete
      flow.

4. OUT OF SCOPE / DEFERRED (deliberate, not gaps)
----------------------------------------------------
- ML-based or LLM-assisted file classification (3a).
- Continuous/real-time background Desktop watching (3d) - on-demand only.
- Fully custom user-authored rule builder UI for the organizer - only the
  built-in game-platform preset ships in v1 (3d). Data model exists
  (OrganizerRule) but no UI writes to it.
- Orphaned game-install leftover detection (3g).
- Network drive scanning (3h).
- SSD health monitoring / TRIM / SMART data (3n).

5. KNOWN GAPS (in scope, designed, not yet fully implemented)
------------------------------------------------------------------
Resolved in the latest round (previously listed here, now IMPLEMENTED -
see the relevant 3x section for detail): UAC elevation prompting,
Recycle Bin action, removable-drive opt-in UI, before/after report UI,
Disk Scan/Treemap header drive stats, Dashboard auto-refresh.

Also resolved (user-reported, this round): Disk Scan/Treemap load
performance against a real large drive root, and the treemap layout
squeezing most items into unreadable slivers - see 3f.

Still open:
- Loose-desktop-file-count "nudge" notification (mentioned in early
  Desktop Organizer discussion) was not built (3d).
- Date-based sorting and custom keyword/path rules for the Desktop
  Organizer are not built (3d) - type-based + game-platform preset only.
- UAC elevation retry (3b/2) is implemented and unit-tested at the
  plumbing level, but the actual "click through a real UAC prompt"
  path could not be exercised by automated testing (a UAC prompt runs
  on Windows' secure desktop by design) - worth a manual end-to-end
  check the next time Windows Update leftovers actually need it.
- Disk Scan/Treemap total completion time for a genuinely huge folder
  (e.g. C:\Windows on a large drive) is still bound by real disk I/O
  and antivirus real-time-scan overhead per file, which no amount of
  in-app parallelism fully eliminates - the fix so far makes results
  appear progressively (usable within ~1s) rather than making the
  single biggest folder finish instantly. Not re-verified with a fresh
  timing number after the final flat-parallel rewrite (the app window
  was minimized/in use during that verification pass) - worth spot-
  checking against C:\ again.

6. STATUS
----------
V1 is built, unit-tested (130 Core tests passing), and verified by
actually running the app end-to-end multiple times. Beyond the original
9-screen build, a follow-up round added Downloads scanning, checkbox
multi-select cleanup, and fixed a real user-reported bug (Windows Temp
quarantine failing entirely over one locked file); a further round closed
out most of the "known gaps" list - UAC elevation retry, Recycle Bin
action, removable-drive opt-in, before/after report UI, Treemap header
drive stats, and auto-refresh are all now implemented; a fourth round
fixed two more user-reported Disk Scan problems (slow load against a
real large drive, unreadable sliver layout) with a proper squarified
treemap algorithm and a flat (non-nested) parallel size computation.
Several real bugs were found and fixed along the way, all through live
testing against the user's actual drives rather than synthetic data
alone: two UI-freeze bugs (Cleanup Suggestions/Treemap scanning
synchronously on the UI thread; later, bulk quarantine doing the same),
the Windows Temp whole-folder-move failure, and the treemap performance/
layout issues. All work is committed and pushed to the GitHub repository
listed at the top of this document. Remaining work is the short list in
section 5 - a nudge notification and custom organizer rules (both minor),
a manual end-to-end check of the UAC elevation prompt, and a fresh
Disk Scan timing spot-check against C:\ after the latest performance
rewrite.

- Fixed (user-reported, 3f): Disk Scan against the real C:\ root both
  loaded very slowly and rendered mostly-unreadable slivers. Replaced
  the slice-based TreemapLayoutEngine with the standard squarified
  algorithm (regression-tested: 25 equal items, no rectangle exceeds a
  6:1 aspect ratio). Went through two performance iterations, each
  live-timed against the real drive: subfolder-level-only parallelism
  still took 30+ seconds (one huge folder dominates regardless of
  siblings); nesting a second parallel layer inside that didn't help
  either (~39s, likely thread-pool contention). Final design: one flat
  parallel operation across every leaf directory of the whole tree
  combined, plus progressive UI streaming (15 of 25 items appeared
  within 0.5s in testing) and a configurable minimum-size filter that
  buckets small items into "Other (small items)". 9 new/changed tests
